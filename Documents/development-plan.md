# 在线麻将开发计划

## 1. 开发阶段概览

当前开发计划分为六个阶段：

1. 完成麻将核心玩法算法和电脑玩家算法验证。
2. 完成 Linux 下基础服务器搭建。
3. 完成账号管理模块和数据库准备。
4. 完成登录前端页面。
5. 完成麻将游戏前端显示画面。
6. 合并麻将游戏核心业务算法。

## 2. 第一阶段：核心玩法算法与电脑玩家算法验证

### 2.1 阶段目标

完成麻将核心规则的算法验证，并验证电脑玩家可以按照规则参与对局。

本阶段不要求完成正式前端页面，也不要求接入服务器业务流程。重点是把麻将规则和电脑玩家算法做成可测试、可复用的核心模块。

### 2.2 功能点

- 定义麻将牌的数据结构。
- 定义玩家、牌墙、手牌、弃牌区、公开组合等数据结构。
- 实现洗牌。
- 实现发牌。
- 实现摸牌。
- 实现打牌。
- 实现吃。
- 实现碰。
- 实现杠。
- 实现胡。
- 实现过。
- 实现回合流转。
- 实现基础胜负判断。
- 实现基础结算。
- 实现电脑玩家合法动作选择。
- 实现电脑玩家出牌策略。
- 实现命令行或测试脚本模拟完整牌局。

### 2.3 规则要求

- 初期采用标准麻将规则。
- 代码结构需要支持后续扩展地方规则。
- 后续需要支持四川麻将。
- 后续需要支持禁用“吃”等规则配置。

### 2.4 输出物

- 麻将核心算法模块。
- 电脑玩家算法模块。
- 单元测试。
- 自动模拟牌局测试。
- 规则扩展设计说明。

### 2.5 验收标准

- 能通过测试脚本完成一局模拟对局。
- 电脑玩家能执行合法动作。
- 非法动作会被核心算法拒绝。
- 标准麻将基础流程可跑通。
- 规则模块没有和页面、数据库、服务器强绑定。

## 3. 第二阶段：Linux 基础服务器搭建

### 3.1 阶段目标

在本地 Ubuntu 虚拟机上完成基础服务器搭建，并确保可以通过浏览器访问。

本阶段不需要运行麻将相关业务。

### 3.2 功能点

- 准备本地 Ubuntu 虚拟机。
- 安装基础运行环境。
- 搭建一个最小 Web 服务。
- 配置服务监听地址和端口。
- 确认宿主机浏览器可以访问 Ubuntu 虚拟机中的服务。
- 提供健康检查页面或简单首页。

### 3.3 输出物

- Ubuntu 虚拟机环境。
- 最小 Web 服务。
- 本地访问说明。
- 服务器启动命令。

### 3.4 验收标准

- Ubuntu 虚拟机内服务可以正常启动。
- 宿主机浏览器可以访问服务器页面。
- 页面能显示简单内容，例如服务运行状态。
- 此阶段不包含麻将业务逻辑。

## 4. 第三阶段：账号管理模块与数据库

### 4.1 阶段目标

完成账号管理模块，并准备数据库存储玩家信息。

系统需要有一个管理员账号，由管理员管理玩家账号的创建和删除。

### 4.2 功能点

- 选择并初始化数据库。
- 设计用户表。
- 创建管理员账号。
- 实现管理员身份。
- 实现玩家账号创建。
- 实现玩家账号删除。
- 实现玩家账号列表查询。
- 实现密码哈希存储。
- 实现基础接口。

### 4.3 数据表初稿

用户表至少包含：

- 用户 ID。
- 用户名。
- 密码哈希。
- 用户角色。
- 创建时间。
- 更新时间。

### 4.4 输出物

- 数据库配置。
- 用户表。
- 管理员初始化方式。
- 账号管理接口。
- 账号管理模块测试。

### 4.5 验收标准

- 数据库可以保存玩家信息。
- 系统存在管理员账号。
- 管理员可以创建玩家账号。
- 管理员可以删除玩家账号。
- 玩家不能自行注册账号。

## 5. 第四阶段：登录前端页面

### 5.1 阶段目标

完成登录页面，确保玩家和管理员都可以登录系统。

### 5.2 功能点

- 制作登录页面。
- 支持用户名输入。
- 支持密码输入。
- 支持登录提交。
- 支持登录失败提示。
- 登录成功后保存登录态。
- 根据角色跳转页面。
- 管理员进入账号管理页面。
- 玩家进入游戏入口页面。

### 5.3 输出物

- 登录页面。
- 登录接口联调。
- 登录态处理。
- 管理员登录流程。
- 玩家登录流程。

### 5.4 验收标准

- 管理员可以登录。
- 玩家可以登录。
- 错误账号或密码不能登录。
- 管理员和玩家登录后进入不同页面。
- 未登录用户不能访问受保护页面。

## 6. 第五阶段：麻将游戏前端显示画面

### 6.1 阶段目标

完成麻将游戏前端显示画面，重点是每个玩家看到的游戏画面。

本阶段可以先使用模拟数据驱动页面，不要求马上接入完整业务算法。

### 6.2 功能点

- 设计 PC 端麻将桌布局。
- 设计移动端麻将桌布局。
- 展示当前玩家手牌。
- 展示其他玩家区域。
- 展示弃牌区。
- 展示当前回合。
- 展示吃、碰、杠等公开组合。
- 展示可操作按钮。
- 展示对局提示信息。
- 支持不同玩家视角的数据展示。

### 6.3 玩家视角要求

- 当前玩家能看到自己的手牌。
- 当前玩家不能看到其他真实玩家的手牌。
- 当前玩家能看到公开弃牌。
- 当前玩家能看到公开组合。
- 当前玩家能看到当前轮到谁操作。

### 6.4 输出物

- 麻将游戏页面。
- PC 端显示效果。
- 移动端显示效果。
- 模拟牌局数据。
- 不同玩家视角展示 Demo。

### 6.5 验收标准

- 页面能清晰展示麻将桌。
- 当前玩家手牌可见。
- 其他玩家手牌不可见。
- 公开信息展示正确。
- PC 浏览器可用。
- 移动端浏览器可用。

## 7. 第六阶段：合并麻将游戏核心业务算法

### 7.1 阶段目标

将第一阶段完成的麻将核心业务算法合并到整体系统中，使前端显示、账号系统和服务端业务形成闭环。

### 7.2 功能点

- 服务端接入麻将核心算法模块。
- 创建游戏实例。
- 将玩家账号映射到游戏座位。
- 接收玩家操作。
- 调用核心算法校验操作。
- 更新牌局状态。
- 为每个玩家生成对应视角数据。
- 推送或返回牌局状态给前端。
- 接入电脑玩家。
- 完成一局游戏流程。

### 7.3 输出物

- 已接入服务端的麻将核心算法。
- 玩家操作接口。
- 玩家视角状态接口。
- 电脑玩家接入流程。
- 完整对局联调 Demo。

### 7.4 验收标准

- 玩家登录后可以进入麻将游戏。
- 游戏可以创建并开始。
- 玩家操作会进入核心算法校验。
- 非法操作会被拒绝。
- 游戏状态能反映到前端画面。
- 不同玩家看到的牌局信息符合规则。
- 电脑玩家可以参与对局。
- 能完整跑通一局游戏。

## 8. 阶段依赖关系

推荐执行顺序：

```text
第一阶段 核心算法
  |
第二阶段 基础服务器
  |
第三阶段 账号管理
  |
第四阶段 登录页面
  |
第五阶段 游戏前端画面
  |
第六阶段 核心业务合并
```

其中第一阶段和第二阶段可以并行推进，因为核心算法初期不依赖服务器。

第五阶段也可以在第六阶段之前使用模拟数据开发，避免等待完整业务合并。

## 9. 当前优先级

最高优先级：

- 第一阶段核心算法。
- 电脑玩家算法。
- 标准规则和规则扩展接口设计。

第二优先级：

- Ubuntu 虚拟机基础服务器。
- 账号管理和登录。

第三优先级：

- 麻将前端显示画面。
- 核心业务合并。
