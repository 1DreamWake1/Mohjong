# 四川麻将规则扩展设计

## 1. 目标与边界

本文定义四川麻将接入 `mahjong-core` 所需的状态和规则边界，不把未完成的地方规则暴露为可选玩法。阶段 16 先完成计分模式和接口拆分，完整可玩版本安排在后续独立阶段。

四川麻将不能只通过禁用“吃”和替换番表实现。换三张、定缺、血战到底、刮风下雨和查叫都会改变对局阶段、玩家状态、结束条件或多次结算流程，需要扩展 reducer 状态机。

## 2. 规则能力拆分

### 2.1 开局阶段

- `exchangeThreeTiles`：发牌后进入换三张，记录每位玩家选牌和交换方向。
- `chooseMissingSuit`：换牌结束后进入定缺，记录每位玩家选择的万、筒或条。
- 所有玩家提交完成前，不进入常规摸打阶段。

建议新增阶段：

```ts
type SichuanGamePhase = "exchange-three" | "choose-missing-suit" | "playing" | "settling" | "ended";
```

### 2.2 出牌约束

- 玩家手中仍有定缺花色时，只能打出该花色。
- 定缺牌不能参与胡牌结构。
- 四川预设禁用“吃”，碰、杠和胡仍由响应窗口处理。

出牌合法性应由核心 reducer 统一判断，Bot 和前端只读取合法动作，不能各自复制约束。

### 2.3 血战到底

- 玩家胡牌后标记为 `won`，退出后续摸打和响应，但牌局不立即结束。
- 当前回合需要跳过已胡玩家。
- 牌局在仅剩一名未胡玩家或牌墙耗尽时结束。
- `winnerSeatIndex` 和单个 `score` 需要升级为多次胡牌与多玩家结算记录。

建议的结算事件：

```ts
type WinSettlement = {
  fanTotal: number;
  fromSeatIndex?: number;
  pointsBySeat: [number, number, number, number];
  winnerSeatIndex: number;
  winType: "selfDraw" | "discard";
};
```

### 2.4 杠分与牌局结束结算

- 刮风下雨作为即时分数事件记录，不能混入最终胡牌番型。
- 牌墙耗尽后执行查叫；未听牌玩家向听牌玩家结算。
- 花猪和退税属于结束阶段结算策略，应与常规胡牌计分分离。
- 所有分数变化保存为可回放事件，历史快照展示累计分数和结算原因。

## 3. 计分接口

阶段 16 已让 `scoring.mode` 生效：

- `standard`：`底分 + 有效番数 × 每番分值`。
- `sichuan`：`底分 × 2^有效番数`。
- `fanLimit`：限制参与点数计算的番数，但保留原始 `fanTotal` 用于展示。
- `minimumFan`：限制允许声明胡牌的最低番数，由 reducer 的自摸和点炮合法动作统一读取。

四川番型表、根数、杠分和多玩家支付矩阵应由独立计分模块实现，不继续扩大当前单手牌 `calculateScore` 的职责。

## 4. 后续实施阶段

1. 四川预设与番型：牌组、禁吃、基础番型、番数和封顶配置。
2. 换三张与定缺：新增动作、阶段状态、Bot 选择和玩家视图。
3. 血战到底：多胜者、跳过已胡玩家、多次胡牌结算。
4. 刮风下雨与终局结算：即时杠分、查叫、花猪和退税。
5. 产品闭环：房间规则选择、牌桌交互、历史回放和长局模拟。

每一步都必须保持简单规则和标准规则回归测试通过，未完成完整闭环前不在房间创建界面提供四川预设。
