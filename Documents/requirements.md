# 在线麻将产品需求

## 1. 产品范围

本项目提供可在 PC 和移动端浏览器运行的在线麻将系统，支持管理员维护账号、真人玩家创建和加入房间、Bot 补位、实时对局、断线恢复及历史回放。

当前版本面向单机或小规模测试部署，不以商业化、高并发或多实例为目标。

## 2. 用户角色

### 管理员

- 登录管理后台。
- 创建、删除玩家账号并重置密码。
- 查看全部历史对局、结算、事件快照和当前活跃房间。
- 查看连接状态与最近持久化错误。

### 玩家

- 使用管理员分配的账号登录，不开放自助注册。
- 创建、加入、离开和准备房间。
- 在人数不足时使用 Bot 补位开局。
- 完成摸牌、出牌、碰、杠、胡、过等合法操作。
- 查看自己的历史对局和事件级牌桌回放。
- 刷新或短暂断线后恢复当前房间和玩家视角。

### Bot

- 仅使用服务端可见的合法信息决策。
- 优先胡牌，并结合牌型进张、碰杠收益和弃牌风险行动。
- 接管离线或超时玩家；真人恢复连接后可重新接管。

## 3. 当前规则

快速对局以 [simple-rules.md](./simple-rules.md) 为验收基线：

- 使用万、筒、条三门牌，不使用字牌。
- 不允许吃，允许碰、杠、点炮胡和自摸。
- 服务端负责洗牌、合法动作、响应优先级、结算和玩家视角过滤。
- 规则预设和计分策略可配置，四川麻将作为独立后续阶段实现。

## 4. 核心功能

### 账号与权限

- 密码必须哈希存储。
- API 和 Socket.IO 均校验身份与房间权限。
- 玩家不能读取他人完整手牌或不属于自己的历史详情。
- 管理员接口与玩家接口严格区分。

### 房间与实时对局

- 房间最多四个座位，支持真人和 Bot 混合。
- 服务端是唯一权威状态源，客户端只提交意图。
- 每位玩家看到独立的脱敏视角。
- 操作和弃牌响应有倒计时；单人模式真人玩家不超时。
- 断线玩家经过宽限期后由 Bot 接管。
- 进行中牌局通过恢复快照跨进程重启恢复。

### 历史与诊断

- 持久化对局记录、事件、结算结果和脱敏牌桌快照。
- 玩家只能查询参与过的对局，管理员可查询全部记录。
- 历史详情支持筛选、逐事件回放和结算调试。

## 5. 非功能要求

- TypeScript 严格模式，核心规则独立于 Web 和服务框架。
- SQLite 作为当前单实例数据库；多实例前必须评估 PostgreSQL 和分布式状态。
- Docker Compose 提供 Web、API 和 Socket.IO 同源入口。
- 提供存活检查、就绪检查、结构化日志和优雅停机。
- 数据库、密钥、日志和备份文件不得提交 Git。
- 关键规则、权限、恢复和部署路径必须有自动化测试或可重复验收步骤。

## 6. 暂不包含

- 广告、充值、支付、商城和积分经济。
- 用户自助注册、找回密码和第三方登录。
- 观战、聊天、匹配排行和赛事系统。
- 多 Server 实例和跨节点房间迁移。
- 完整四川麻将玩法。

## 7. 验收标准

- 管理员能够完成玩家账号管理和对局诊断。
- 一至四名真人能够创建房间并用 Bot 补位完成一局。
- 非法操作被服务端拒绝，私有手牌不会泄露。
- 碰、杠、胡、过、流局、倒计时和断线接管按规则工作。
- 重连和进程重启后可恢复有效牌局。
- 对局结束后可查询历史、结算和事件快照。
- Docker Compose 能完成迁移、启动、健康检查和优雅停机。
